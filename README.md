### 六轮迭代：从 88% 到 100%

每一轮失败都定位到**机制层根因**，不是靠调 prompt 蒙过去的：

| 轮次 | 版本 | 通过率 | 关键根因 |
|---|---|---|---|
| R-1 | fixed8 | 44/50（88.0%） | A4/A5 安全红线未生效 → 新增规则兜底节点 N12b |
| R-2 | fixed9.7 | 48/52（92.3%） | 检索链路修复（embedding 切通义千问 + 4 库重建） |
| R-4 | fixed9.16 | 29/52（55.8%） | **docstring 里 `\{` 触发 SyntaxWarning，被 Dify 沙箱升级为节点失败** |
| R-5 | fixed9.17 | 45/52（86.5%） | 执行故障清零（`"""` → `r"""`）；暴露纯 SKU 码检索召回失败 |
| **R-6** | **fixed9.18** | **52/52（100%）** | 检索 query 加品类词、top_k 4→10，出单量 3→6 |

## 关键设计决策

**1. 安全红线用机制保证，不靠提示词自觉**

超阈值转人工、拒答不编造这类红线，全部放在代码节点（N12b 规则兜底 R0–R8，fail-closed）重算，
而不是依赖 LLM 遵守 prompt。模型可能被绕过，代码不会。

**2. 路由与阈值一律放代码层**

V1–V9 校验全部是代码级硬校验，防止模型自证通过。

**3. 双层流「AI 先做、人只审」**

AI 生成报价草稿，人工只做审核确认。报价单绝不自动发出。

**4. 验收指标按「期望行为」分组计分**

原指标「闭环率 ≥40%」的分母是全部样本，而样本中 32 条设计上就该转人工——
这等于用样本难度惩罚系统。52 条样本里期望可闭环的只有 20 条，
**理论上限就是 38.5%，数学上永远达不到 40%**。

改为三项行为正确率后（自动闭环 / 报价草稿 / 强制转人工），R-6 实测三项均 100%。
详见 [D12 §6.2](deliverables/D12_测试询盘样本集与验收回归报告.md)。

## 技术栈

- **平台**：Dify（云端 SaaS 主推，私有化 Docker Compose 备选）
- **工作流**：31 节点 / 33 边，四终态（自动答复 / 报价待确认 / 转人工 / 归档）
- **模型**：DeepSeek（LLM 节点）+ 通义千问 `text-embedding-v1`（知识库检索）
- **知识库**：4 库 42 条，L1/L2/L3 三级机密分类
- **验收**：52 条样本，覆盖三难度（直接可答 / 需人工确认 / 拒答）
