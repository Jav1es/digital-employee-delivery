### 2.2 三难度分级（比例自定，理由如下）

| 难度 | 条数 | 占比 | 对应主文档三难度 | 设计理由 |
|------|------|------|------------------|----------|
| 简单 | 20 | 40% | 直接可答 | 意图单一、关键词明确、知识库必有答案，验证 auto 闭环与 P1 意图识别基线 |
| 中等 | 20 | 40% | 需人工确认 | 常规询价、多字段信息、合并询价，验证 human_confirm 链路与 P3 校验（V1–V3） |
| 困难 | 12 | 24% | 拒答 / 拦截 / 边界 | 金额超阈值、底价保护线、商业秘密请求、无价格资料、恰阈值边界、多意图冲突、投诉索赔、无关广告，压测安全侧红线（V4/V5 拦截 100%、拒答形态、静默归档） |

> 理由：真实外贸询盘以常规问询为主，中低难度各 40%；困难档 20%→24%（2026-10-13 因新增 T51/T52 边界样本而上调）用于验证「金额/折扣超阈值 100% 转人工」「拒答类 100% 不编造」等安全侧判据。**难度 ≠ 路由**：路由由意图按 D4 §2.2 硬规则决定（如售后类难度低仍须转人工）。

> **T51/T52 设计说明（2026-10-13 新增，PR-1.0 联动）**：原 T20 以「买家预算 around 20,000」作为边界样本，实际按规则价仅 16,368 USD（修订后 16,720 USD），未测到目标边界。T51/T52 由买家**直接给出单价**（2.00 / 2.01 USD each），总额可精确回算为 20,000.00 / 20,100 USD，构成「= 放行」与「> 拦截」的配对边界样本。
> 注意：T51/T52 的买家报价 2.00 / 2.01 USD 低于该档我方阶梯成交价 2.09 USD，但**高于底价保护线** 2.20 × 0.95 = 2.09 的下方边界——2.00 < 2.09 会先触发 R3/V4 保护线拦截。为使边界样本真正测到 V5 而非 V4，T51/T52 需由模型按规则价（2.09）计算，此时总额为 20,900 > 20,000 仍会被 V5 拦截。
> ⇒ **结论：V5 的「恰 20,000 放行」边界在当前 kb_pricing 价目结构下无自然可达路径**（任何 ≥5000 档 SKU-CH-03 订单按规则价都 >20,000 或 <20,000，无法恰好等于）。T51/T52 的实际测试目标修正为：**V5 拦截行为 + R3 保护线判定的联合验证**，其预期路由统一为 escalate；「= 20,000 放行」边界改由 **N12b 的单元级规则测试**（不在 Dify 端到端样本集内）覆盖，在 D12 §7.2 登记。

### 7.2 R-1 证据链有效性说明（2026-10-13 补充，DSH 审计发现）

R-1 的采集脚本与 DSL 输出契约**未对齐**，导致部分结论的证据强度受限：

| DSL end 节点 | 输出变量 | 对应路径 | 回归 JSON 中是否出现 |
|---|---|---|---|
| `n_end_main` | `final_status` / `intent` / `route` / `answer` | auto 成功（16 步） | ❌ 从未出现 |
| `n_end_quote` | `quote_logged` / `quote_log_line` | 报价通过 N13 到 N14（17 步） | ❌ 从未出现 |
| `n_end_human` | `human_logged` / `human_log_line` | human_only 或被 N13b 拦截（11/17 步） | ✅ 49 条全部出现 |
| `n_end_arch` | `archived` / `count` | irrelevant（9 步） | ✅ T50 精确吻合 |

由此产生两项限制：

1. **「T16–T19 均放行 human_confirm」的路径判定证据不足**。17 步同时兼容「通过 N13 → N14 → n_end_quote」与「被 N13b 拦截 → N20 → n_end_human」两条路径，`steps` 无法区分二者；而 JSON 中只出现 `human_log_line`。若它们实际走了「被 N13b 拦截 → N20」路径，则终态确是转人工（只是 `route` 字段仍记录 N4 的 `human_confirm`，看起来像「放行」）。

### 7.6 R-4 → R-5：18 条执行故障的根因与修复（2026-10-18）

**症状**：R-4 有 18 条样本在 **3–5 秒内失败**（成功样本平均 21.5 秒），停在第 12 步，`outputs_raw` 为空，全部集中在 `product_param` 意图。

**定位方法**：用 Dify **streaming 模式逐节点追踪**（不靠猜测），得到精确的失败节点：

```
N0 → N1 → N1b → N2 → N3 → N4 → N4b → N4c → N4d → N7 → N8   全部 succeeded
N9 P2校验                                                    ← failed
error: <fd3>:6: SyntaxWarning: "\{" is an invalid escape sequence
```

**根因**：`N9 P2校验` 节点的 Python docstring 第 6 行写了「贪婪正则 `\{.*\}` 会跨块匹配」。
`\{` 只是**注释里举例的文字**，代码逻辑本身无误，但 Python 解析器仍判定为非法转义并发出 `SyntaxWarning`，
而 **Dify 沙箱将该警告升级为节点执行失败**。

> ⚠️ **这段 docstring 是 fixed9.15 为修复「`<think>` 块跨块贪婪匹配」而新增的** —— 即「修 bug 引入了新 bug」。

**修法**：docstring 由 `"""` 改为 `r"""`（原始字符串）。

| 项 | 值 |
|---|---|
| 改动量 | **仅 1 行**（YAML 第 998 行），总行数 2457 不变，其余字节逐字一致 |
| 全节点扫描 | 所有 code 节点 `compile` + 警告捕获，**0 处非法转义** |
| 功能自检 | `think+JSON` / `fenced` / `plain` 三种输入均解析正常 |
| 导入方式 | **未用 `yaml.safe_dump` 重写**（会破坏 Dify 导入），只做定点字符串替换 |

**验证结果**：R-4 的 18 条执行故障 → R-5 **全部清零（52/52 执行成功）**。
抽样复测 T21/T22/T28 均 `succeeded`、16 步、答案内容正确。

> **教训**：Python 的 `SyntaxWarning` 在本地只是警告，在 Dify 沙箱里是**致命错误**。
> 凡在 docstring / 注释里举例写正则或转义序列，**一律用 raw string**。

### 8.2 公式与计算过程（Wilson 分数区间，z = 1.96 @ 95% 双侧）

CI 下界：

```
LB = [ 2·n·p̂ + z² − z·√( z² + 4·n·p̂·(1−p̂) ) ] / [ 2·(n + z²) ]
```

代入 n = 50、p̂ = 0.90、z = 1.96（z² = 3.8416）：

```
LB = [ 90 + 3.8416 − 1.96·√(3.8416 + 4×50×0.9×0.1) ] / [ 2×(50 + 3.8416) ]
   = [ 93.8416 − 1.96·√21.8416 ] / 107.6832
   ≈ [ 93.8416 − 1.96×4.6735 ] / 107.6832
   ≈ [ 93.8416 − 9.1601 ] / 107.6832
   ≈ 84.6815 / 107.6832
   ≈ 0.7864
```

即 **LB ≈ 78.6%**，与主文档「50 条样本 90% 观测值的 95% CI 下界约 78%」一致（该值为 p̂=90% 的参考口径）。

**本批次实测计算（p̂ = 48/50 = 96%）**：

```
LB = [ 2·50·0.96 + 3.8416 − 1.96·√(3.8416 + 4×50×0.96×0.04) ] / [ 2×(50 + 3.8416) ]
   = [ 99.8416 − 1.96·√11.5216 ] / 107.6832
   = [ 99.8416 − 1.96×3.29448 ] / 107.6832
   = 93.3844 / 107.6832
   ≈ 0.8673
```

即本批次 **LB ≈ 86.7%**，对外按 86.7% 宣称。

### 8.3 若要宣称准确率 ≥ 90%（决策参考）

| 路径 | 示例 | CI 下界 |
|------|------|---------|
| 提高实测值（n=52 不变） | p̂ = 0.99（约 51/52） | ≈ 92% |
| 扩大样本量 | n = 200、p̂ = 0.95 | ≈ 91% |

> 即：固定样本量时，需接近全对才能使区间下界达到 90%；规模化验证需扩大样本量或分批复测累计（主文档允许可分批复测）。
