## 1. 接入形态选型

### 1.1 候选形态

| 平台 | 形态 | 消息能力 | 回调能力 | 审批/卡片能力 |
|------|------|----------|----------|---------------|
| 企业微信 | 自建应用（企业内部应用） | 收消息 + 主动推送 | 完整（enter_agent / message 事件） | 支持应用消息卡片（审批卡片可落地） |
| 企业微信 | 群机器人（webhook） | 仅主动推送，不能收消息 | 无 | 仅文本/图文，无卡片审批 |
| 钉钉 | 企业内部应用 | 收消息 + 主动推送 | 完整（消息回调订阅） | 支持工作通知 + 卡片 |
| 钉钉 | 自定义机器人（webhook） | 仅主动推送，不能收消息 | 无 | 受限 |

### 1.2 主推形态与理由

**主推：企业微信自建应用（企业内部应用）；备选：钉钉企业内部应用（同构配置）。**

理由：

1. **消息闭环能力**：数字员工需要"接收买家询盘 → 处理 → 主动发送答复/报价单/审批卡片"完整闭环；群机器人与自定义机器人（webhook）只能单向推送，无法接收群消息与私聊消息，不满足 D3 N0 接入节点需求。
2. **审批卡片落地**：D3 N14 生成草稿后需推送审批卡片供主管审批，N15 外部审批状态机需回调更新状态；仅企业应用支持应用消息卡片与回调，webhook 形态不可行。
3. **安全权限可控**：企业应用支持可见范围、可信 IP、回调签名验签（详见 §3），满足本文件安全权限要求；webhook 形态无成员鉴权与回调验签能力。
4. **与目标客户办公环境一致**：案例A 目标客户（广州星航贸易有限公司，虚构典型客户）使用企业微信办公，群聊触达与审批流均在企微侧完成，符合客户画像与 D3 N8 企微推送的预设通道。

> 钉钉企业内部应用作为备选形态，配置项与企微同构（appKey/appSecret ↔ AgentId/Secret，订阅回调 ↔ 接收消息服务器），仅密钥体系与签名算法不同；后续章节以企微主推形态展开，钉钉差异点单独标注。

## 2. 机器人创建与回调配置

### 2.1 企业微信自建应用（主推）

| 配置项 | 取值说明 | 备注 |
|--------|----------|------|
| 企业 ID（corp_id） | 企业微信管理后台「我的企业」获取 | 全局唯一 |
| 应用 AgentId / Secret | 自建应用「应用详情」获取 | Secret 仅服务端保存，禁止入库明文 |
| 接收消息服务器 URL（回调 URL） | `https://<域名>/im/callback/wecom` | 需 HTTPS，公网可达 |
| 回调 Token + EncodingAESKey | 回调配置页生成 | 用于验签与加解密 |
| 可信 IP | 配置服务端出口 IP 白名单 | 防止未授权调用 |
| 应用可见范围 | 配置为「外贸部全员 + 主管」（§3.1 细化） | 影响接收与推送范围 |

回调事件订阅（需在应用「接收消息」中开启）：

| 事件 | 触发时机 | 对接节点（D3） |
|------|----------|----------------|
| `enter_agent` / `text` 消息事件 | 成员在企业微信内发消息（含群内 @） | N0 接入 |
| 群聊 @ 消息 | 群成员 @ 应用机器人 | N0 接入（§2.3） |
| 审批回调 | N15 外部审批完成后回传 | N15b（签名 + 幂等） |

### 2.2 钉钉企业内部应用（备选）

| 配置项 | 取值说明 |
|--------|----------|
| appKey / appSecret | 钉钉开放平台企业内部应用获取 |
| 消息接收 URL | `https://<域名>/im/callback/dingtalk` |
| aes_key / token | 订阅回调配置生成 |
| 权限范围 | 勾选「企业内机器人」「消息接收」「工作通知」权限点 |
| IP 白名单 | 钉钉开放平台应用详情配置 |

> 钉钉侧回调验签算法与企微不同（timestamp + sign 参数），需在接入层适配；节点语义与 D3 完全一致（见 §5）。

### 2.3 群聊 @ 触发与消息回执机制

**@ 触发流程（企微主推）：**

1. 群成员发送含 @ 的消息 → 企微回调携带 `msg_id`、`from_userid`、群 `chat_id`、消息正文 `content` 推送至回调 URL；
2. N0 接入层做**幂等去重**（按 `msg_id` 去重，重复回调不重复处理，对应 D3 N0→N1）；
3. N0 接入层**立即返回消息回执**（同步 ack），回执时间戳记为 `T_ack`；回执口径只含接入层确认，不含大模型推理时间；
4. 消息正文带 @ 标记与 `chat_id`，进入 N1 预处理与后续工作流路由。

**触发边界：**

- 群聊仅响应**明确 @ 数字员工**的消息；未 @ 的群消息不处理、不计数（防止群内闲聊进入流程）；
- 私聊消息全部接收并处理；
- 无关内容（D3 §7.2 中占比 2% 的无关/广告）按 N21 静默归档，不向群内推送任何回复。

**消息回执机制（对接主文档验收）：**

| 项 | 配置/口径 |
|----|-----------|
| 回执方式 | 接入层收到回调后 3 秒内同步返回成功 ack（HTTP 200）；处理异常时同样先回执，异步补发失败通知 |
| 回执时间戳 | `T_ack` 落库（D9 埋点字段，见 D9 §4） |
| 回执口径统计 | 仅统计"接入层 ack 到客户可见反馈"之间的确认时长，**不含大模型推理、审批等待时间** |
| 与端到端指标关系 | 与 Phase 4 看板端到端平均响应时间**不得互证**（见 §0） |

## 3. 安全权限

### 3.1 可见范围与访问分级

- **应用可见范围**：仅开放给「外贸部成员 + 审批主管」；禁止全员可见、禁止开放给非业务部门；
- **数字员工响应边界**：仅响应企业内已验证成员（`from_userid` ∈ 可见范围）发来的消息；群外人员 / 未授权成员消息一律拒绝并记日志；
- **报价数据访问分级（对齐 D5 §7.1）**：L3 报价数据（底价/折扣上限）仅主管与系统身份 N11 可用；数字员工不得向买家披露底价、成本、折扣上限（对齐 D4 §3.1/§4.1 商业秘密拒答路径）。

### 3.2 敏感操作权限

| 操作 | 权限控制 | 对齐口径 |
|------|----------|----------|
| 报价审批（N14 审批卡片） | 卡片仅推送给授权审批人（外贸主管/负责人）；审批人列表由企业微信通讯录角色维护 | D3 N14/N15、D5 §7.1 L3 |
| 发送报价单（N16） | 仅审批通过后由工作流发送；数字员工无独立"主动发报价"入口 | D3 N15/N16 |
| 转人工（N20） | 转人工通知推送给对应业务员，附 P5 脱敏摘要 | D3 N20、D4 §5.2 |
| 脱敏校验 | 输出前 L6 脱敏校验（正则拦截完整手机号/邮箱）；命中则脱敏后重发并记日志 | D4 §7 L6 |
| 摘要脱敏口径 | P5 摘要中姓名保留姓氏+「先生/女士」、公司名保留、联系方式中间四位打码 | D4 §5.2 |

### 3.3 消息鉴权与防伪造

| 层 | 机制 |
|----|------|
| 回调验签 | 企微：校验 `msg_signature` 并解密（Token + EncodingAESKey）；钉钉：校验签名参数。验签失败一律丢弃并告警 |
| 幂等 | N15b 审批回调按审批实例 id 幂等处理，重复回调不重复触发状态变更（对齐 D3 §2.2） |
| 可信来源 | 服务端出口 IP 白名单；回调 URL 仅接受企微/钉钉平台来源 |
| 密钥管理 | AgentId Secret / appSecret / EncodingAESKey 存服务端密钥管理，禁止写入代码库与配置文件明文 |
| 日志留痕 | 收/发消息、审批、转人工均记操作日志（对齐 D5 §7.2 日志层），日志访问受权限控制 |
| 用户隐私 | 买家个人信息按 D4 §5.2 脱敏口径展示；进向量库前已完成脱敏与分级（对齐 D5 §8） |

## 4. 跨境合规与数据驻留（按 D5 §8 基线）

> 本节以 D5《知识库构建包》§8「云端 RAG 数据驻留基线」为唯一基线来源，D6 负责落地执行口径。

| 合规项 | D5 §8 基线 | D6 落地要求 |
|--------|------------|-------------|
| 区域出境评估 | 存储区域须满足个保法（PIPL）出境评估结论，不满足的区域不选用 | 本案例涉及境外买家个人信息（姓名/公司/联系方式/询盘内容）进入系统，上线前完成出境评估并留存结论；评估结论未通过前，禁止启用境外节点 |
| 存储区域 | 云端 SaaS 形态下区域由服务商决定，区域须写入服务合同/服务条款 | 落盘文档记录所选区域与合同条款引用（区域标注与合同条款归 D7 细化，D6 提供接入侧约束） |
| 默认保留基线 | 默认保留 30 天（可配置）；L3 价格数据最短保留 + 到期即删 | 询盘原文与向量默认保留 30 天；L3 报价数据（底价/折扣上限）采用最短保留策略，到期立即删除 |
| 删除机制 | 删除须同时清除向量、原文、备份副本，并出具删除凭证 | 提供删除流程（清向量 + 清原文 + 清备份副本 + 生成删除凭证），删除凭证留档备查 |
| 跨境传输 | 出境评估部分归 D6；进向量库前已完成脱敏与分级 | 跨境传输链路启用传输加密；仅传输脱敏后数据；出境评估结论归档至本交付物配套台账 |

> 与 D3/D5 的关系：D3 侧不承载数据驻留逻辑，全部按 D5 §8 执行；D6 负责把 D5 基线翻译为 IM 接入层的可执行配置项（区域白名单、保留策略开关、删除任务编排）。

## 5. 与 D3 工作流节点的对接点（以 D3 终稿为准）

| D3 节点 | 节点含义 | D6 对接内容 |
|---------|----------|-------------|
| N0 | IM 接入与消息接收 | 企微/钉钉回调接入，`msg_id / content / sender_id / chat_id / ts` 落库，3 秒回执 |
| N1 | 预处理与去重 | 按 `msg_id` 幂等去重；群消息仅处理 @ 数字员工消息 |
| N6 | 意图识别（P1） | 回调消息进入 P1，路由结果回写 N23 埋点 |
| N8 | LLM P2 知识问答（企微推送） | 自动答复经企微应用消息推送至发起会话/群（引用 D3 终稿 N8 推送形态） |
| N14 | 生成草稿 + 推送审批卡片 | 报价草稿以应用消息卡片推送审批人，附 D3 草稿 JSON 摘要 |
| N15 / N15b | 外部审批状态机 / 审批回调 | 审批卡片点击后回传回调，N15b 验签 + 幂等更新状态 |
| N16 | 发出报价单 | 审批通过后经企微发送报价单给买家，记录发送时间戳（端到端口径终点之一） |
| N20 | P5 转人工摘要 → 转人工 | 转人工通知推送对应业务员，附脱敏摘要 |
| N21 | 静默归档（无关内容） | 不推送、仅计数，回执仍正常返回 |
| N22 | 发送答复（自动闭环终态） | 自动答复推送成功记录 `T_sent`（端到端口径终点） |
| N23 | 状态落库 + D9 埋点 | 各终态写入 N23，供 D9 看板取数（对接 D9 §4 埋点字段） |
| N24a/b/c | 跟单提醒 | 提醒消息经企微推送（业务员/主管/每日 09:00 群汇总，对齐 D4 §5.1 P4） |
