## 3. 清洗与切分规则

### 3.1 通用清洗

| 步骤 | 规则 |
|------|------|
| 格式归一 | PDF/Excel/Word → Markdown；表格转 Markdown 表格（保住行列语义） |
| 噪声清除 | 去除页眉页脚、水印、重复目录、扫描 OCR 错字 |
| 元数据注入 | 每条片段带 `doc_id` / `sku` / `category` / `secret_level` / `version` / `effective_date` |
| 去重 | 按 `sku + 内容哈希` 去重；同 SKU 多版本只保留**当前生效版** |
| 脱敏 | 片段中不得含完整手机号/邮箱/客户名（正则扫描，命中即打码） |

### 3.2 中文切分适配（**重点，中文无空格分词**）

| 资料类型 | 策略 | 参数 |
|----------|------|------|
| 产品手册（长文） | 按**标题层级**切，而非按字数硬切 | 最大 512 token，重叠 64 |
| FAQ | **一问一切**，问句与答案不可分离 | 256 token |
| **价格表 / 底价表** | **整块不切分** | ⚠️ 见下 |
| 汇率 | 单条不切分，按日期整块替换 | — |

> 🔴 **价格表切分红线（必守）**：底价表**不得按行/按字数切分**。
> 若一张「SKU × 数量档」的单价表被切成多段，P3 检索时可能只召回其中一段，导致取到错误档位的价格或漏取 MOQ 阶梯 —— 这正是「误报价」最典型的成因。
> **规则**：单 SKU 的价格表作为**一个完整 chunk 入库**，并在 `doc_id` 中带 `sku` 标识，保证检索可精确定位；若单表超长，按**数量档整档**切分且每片自带完整表头（SKU、币种、单位）。

### 3.3 检索参数

| 参数 | 取值 | 依据 |
|------|------|------|
| Top-K | **4** | D4 §8 |
| 检索模式 | 向量 + 关键词混合 | 中文型号/认证编号关键词命中更好 |
| 相似度阈值 | 低于阈值 → 走无答案路径，**不扩大 K 重试** | D4 §8 |
| 元数据过滤 | 按 `secret_level` 与调用方角色过滤（§7） | 防越权召回 |
| **Embedding 模型** | **通义千问 `text-embedding-v1`（v3 系列可升）** | 2026-10-15 修订，见 §3.4 |

### 3.4 Embedding 供应商（2026-10-15 变更，原 OpenAI 配额阻断）

> **背景（R-2 阻断实证）**：知识库原使用 `langgenius/openai/openai` 作 embedding，2026-10-14 起该 provider 配额耗尽，`semantic_search` 全部返回 `HTTP 400: quota exceeded`，导致 N7/N11a/N11b 召回恒空、P2 问答与 P3 报价链路全灭（N9 正确 fail-closed 转人工，但 auto 链路无法验收）。
>
> **决策（Q4 已拍板）**：embedding 供应商由 OpenAI **切换为通义千问（DashScope）`text-embedding-v1`**；Dify 工作区已配置通义千问 API Key（截图实证：API KEY 1 已配置，支持 LLM / TEXT EMBEDDING / RERANK / SPEECH2TEXT / TTS）。
>
> **LLM 供应商不变**：N3/N8/N12/N20 四个 LLM 节点仍绑定 `deepseek/deepseek-v4-flash`（DeepSeek 无 embedding 产品线，故 embedding 单独走通义千问，两者不冲突）。
>
> **切换后必须执行的动作（缺一不可）**：
> 1. 在 Dify「知识库 → 各库 → 设置」把 Embedding 模型改为通义千问 `text-embedding-v1`；
> 2. **重建索引**——换 embedding 模型后旧向量全部失效，必须对 4 个库重新上传/重建，否则仍召回为空；
> 3. 重建后用**正对照**验证：query `SKU-PC-01` 必须召回 kb_product 中「手机壳产品手册」的 PC-01 片段（含 `iPhone 15 Pro Max` / `TPU`），不得只回传 SKU-CH 系列；
> 4. 正对照通过后重测 T21（auto 链路）与 T01（报价链路），再跑 R-2 全量 52 条。
>
> ⚠️ **向量维度变化风险**：不同 embedding 模型的向量维度不同，换模型后**不能增量更新**，只能整库重建；重建前建议在 D7 部署手册记录本次切换（模型名、日期、重建范围）。

## 4. 版本与更新机制

| 对象 | 更新触发 | 版本动作 | 回归要求 |
|------|----------|----------|----------|
| 报价规则（含价格数据） | 价格档位/折扣阶梯/底价保护线变更 | `PR-MAJOR.MINOR` 递增，更新 D4 §6.3 登记表 | **触发 D12 回归**（D4 §6.4） |
| 汇率 | 每日或按 `validity_days` | 按 `effective_date` 整块替换，旧版留档 | 过期即走无价格资料路径（D4 V7） |
| 产品资料/FAQ | 产品迭代、政策变更 | `doc version` 递增 | 影响问答准确性 → 建议回归 |
| Prompt 体系 | — | `PT-MAJOR.MINOR`（D4 §6.1） | 触发 D12 回归 |

> **版本号三处一致**：知识库元数据 + Dify 工作流变量 + D4 §6.3 登记表（D4 §6.1）。D3 的 N2 节点在运行时校验一致性，不一致即阻断启动。

### 4.1 汇率更新机制（补齐「更新机制」落地）

| 项 | 规则 |
|----|------|
| 取数来源 | 指定公开汇率源（示例：央行/银行间中间价页面），**在 D7 锁定具体来源与抓取方式** |
| 更新频率 | 每工作日更新（周末/节假日不更新）；`validity_days = 7`（审计#14 修订：与 §4 表「每日或按 validity_days」统一为「每工作日」，消除周末口径冲突） |
| 失效处理 | 超过 7 天无更新 → 该汇率片段标记 `expired`，P3 走「无价格资料」路径（**不得用旧汇率报价**） |
| 留档 | 每次更新保留历史值，可回溯某笔报价当时所用汇率 |

### 6.1 `config.yaml`（示例）

### 6.2 `build_kb.py`（骨架，可运行）

```python
#!/usr/bin/env python3
# -*- coding: utf-8 -*-
"""案例A · D5 知识库构建脚本
用法: python build_kb.py --config config.yaml --raw raw/ --out out/
"""
import argparse, hashlib, json, re, sys
from pathlib import Path

def load_config(p):
    try:
        import yaml
    except ImportError:
        sys.exit("需要 PyYAML: pip install pyyaml")
    return yaml.safe_load(Path(p).read_text(encoding="utf-8"))

def mask_pii(text, patterns):
    """PII 脱敏：命中即打码，返回 (脱敏后文本, 命中数)"""
    hits = 0
    for item in patterns:
        text, n = re.subn(item["regex"], "[REDACTED]", text)
        hits += n
    return text, hits

def chunk_text(text, rule):
    """按规则切分。whole_doc 用于价格表：整块不切分（防误报价）"""
    mode = rule.get("mode", "by_heading")
    if mode == "whole_doc":
        return [text]
    size, overlap = rule.get("max_tokens", 512), rule.get("overlap", 64)
    # 生产环境请改用 tokenizer；此处按字符近似（中文 1 token ≈ 1.5 字）
    step = max(1, size - overlap)
    return [text[i:i + size] for i in range(0, len(text), step)] or [text]

def main():
    ap = argparse.ArgumentParser()
    ap.add_argument("--config", required=True)
    ap.add_argument("--raw", required=True)
    ap.add_argument("--out", required=True)
    args = ap.parse_args()

    cfg = load_config(args.config)
    raw_dir, out_dir = Path(args.raw), Path(args.out)
    out_dir.mkdir(parents=True, exist_ok=True)

    for name, spec in cfg["collections"].items():
        records = []
        for f in sorted((raw_dir / name).glob("*.md")):
            text = f.read_text(encoding="utf-8")
            text, hits = mask_pii(text, cfg.get("pii_patterns", []))
            for idx, chunk in enumerate(chunk_text(text, spec["chunk"])):
                # TODO(Phase 1)：doc_id 须含 sku（§3.2 红线，如 {name}-{sku}-{idx:03d}）；
                # 注入 sku/category/effective_date（§3.1）；version 按 collection 区分
                # （kb_pricing 用 pr_version，kb_product/kb_faq 用 doc version，§4）
                records.append({
                    "doc_id": f"{name}-{f.stem}-{idx:03d}",
                    "collection": name,
                    "secret_level": spec["secret_level"],
                    "content": chunk,
                    "content_hash": hashlib.sha256(chunk.encode()).hexdigest()[:16],
                    "version": cfg["version"]["pr_version"],
                })
        # 去重：同 collection 内 content_hash 唯一
        # TODO(Phase 1)：按 sku + 内容哈希去重，并做版本比较（同 SKU 多版本只保留当前生效版，§3.1）
        seen, uniq = set(), []
        for r in records:
            if r["content_hash"] not in seen:
                seen.add(r["content_hash"])
                uniq.append(r)
        with (out_dir / f"{name}.jsonl").open("w", encoding="utf-8") as fh:
            for r in uniq:
                fh.write(json.dumps(r, ensure_ascii=False) + "\n")
        print(f"{name}: {len(uniq)} chunks -> out/{name}.jsonl")

if __name__ == "__main__":
    main()
```

## 7. 访问分级与防泄露（**补齐主文档 Phase 1 动作 2「商业秘密分级」**）

### 7.1 密级定义

| 密级 | 定义 | Collection | 可见角色 |
|------|------|-----------|----------|
| **L3 机密** | 报价规则（含价格数据）：底价、折扣阶梯、底价保护线 | `kb_pricing` | 外贸主管、负责人；**业务员不可见**；**数字员工（系统身份）：仅限报价链路 N11 检索使用，输出层不得落地底价（见 §7.2）** |
| **L2 受限** | 汇率、成本口径 | `kb_fx` | 主管、业务员（只读汇率值） |
| **L1 内部** | 产品手册、FAQ、认证、交期 | `kb_product` / `kb_faq` | 全体员工 + 数字员工 |

### 7.2 防泄露规则（**技术 + Prompt 双层，缺一不可**）

| 层 | 措施 |
|----|------|
| 检索层 | **元数据过滤**：N7/N11 检索时按调用方角色过滤 `secret_level`，L3 不对业务员角色召回；**数字员工以系统身份仅在 N11 报价链路读取 L3（算价必需），其他链路一律不得召回 L3；人通过对话索取底价时由输出层 Prompt 拒绝并转人工（D4 §3.1 第 6 条，审计#11 修订）** |
| 输出层 | **Prompt 硬约束**：P2 遇「索取底价/成本/折扣上限」一律拒绝并转人工（D4 §3.1 第 6 条、`escalate_reason = secret_data_request`） |
| 报价层 | P3 只输出**成交价**，不输出底价、成本、折扣上限（D4 §4.1） |
| 日志层 | L3 片段的召回与引用全量留痕（`doc_id` + 调用方 + 时间），可回溯（D6/D9） |
| 展示层 | 对外答复与报价单**不含**底价/成本字段；P5 摘要对买家信息脱敏（D4 §5.2） |

> **红线**：L3 价格的**召回可见性由检索层元数据过滤强制保证，不依赖模型自觉遵守**——与 D3「路由与阈值一律放 Code 节点」同一原则。**说明（审计#11 修订）**：检索层能强制挡住「召回」，但「P3 输出时不得泄露底价/成本/折扣上限」属生成约束，技术上由 Prompt（D4 §4.1）+ 展示层/日志层兜底（报价单字段白名单、输出后校验）双重保障，**不宣称输出层纯技术强制**。
