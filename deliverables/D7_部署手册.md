## 0. 部署对象与平台口径

案例A（外贸询盘数字员工）的生产形态包含以下可部署组件，本文档统一命名为**部署对象全集**：

| 部署对象 | 形态 | 责任文档 |
|----------|------|----------|
| Dify 平台（工作流编排 + 知识库检索） | 云端 SaaS 主推；私有化 Docker Compose 备选 | D3 §1、本文档 |
| 外部轻量审批服务（自研唯一组件） | 草稿存储 + 状态机 + 签名回调 + 4h 超时扫描 | D3 §4.2、本文档（交接归 D8） |
| IM 接入（企业微信主推 / 钉钉备选） | 回调 URL / Token / EncodingAESKey 等接入配置 | D6 |
| 知识库数据（kb_product / kb_pricing / kb_faq / kb_fx，合计约 42 条示例） | 构建脚本产出 jsonl，上传至 Dify Knowledge | D5 |

**平台口径（与 D3 §1 一致）**：

1. **主推路径**：Dify 云端 SaaS。免运维、开通即用，作为默认演示与生产形态。
2. **私有化备选**：Dify Docker Compose 自托管，用于需要数据本地留存、无外网连接或客户指定私有化交付的场景。
3. **离线备选**：enterprise-agent（自研离线改造版，基于开源框架二次开发），仅用于无网/低配环境演示，Phase 3 备选。**上游项目名与版本须在本文档 §2.5 锁定并注明**（当前待 Phase 1 搭建时锁定，见 §8 待核实项）。
4. **验收双轨（Phase 3 口径）**：云端租户开通 + 配置 → 冒烟测试 ≤ 60 分钟；私有化一键脚本启动 → 冒烟测试 ≤ 30 分钟。冒烟测试覆盖：N0 消息接收回执、P1 意图识别、知识库检索命中、报价草稿生成（详见 D3 §10 验收对照）。

> 说明：D3 §1 载明「所用 Dify 版本未提供可直接用于企微场景的原生人工审批节点」为前提设计，该前提**待 Phase 1 搭建时以实际版本实测核实**；若所用版本已提供原生审批节点，审批服务部署可相应简化（见 §8）。

## 1. 云端 SaaS 主推路径

### 1.1 Dify 云端开通

1. 注册并创建 Dify 云端空间（租户），选择服务区域。**区域选择须满足个保法（PIPL）出境评估结论**（定义源 D1 §9；执行落点 D6 §4 / D5 §8）：涉及境外买家个人信息进入系统，上线前完成出境评估并留存结论；评估结论未通过前，禁止启用境外节点。所选区域须写入服务合同/服务条款，并在运维台账（§7）登记合同条款引用。
2. 开通后确认租户内可用的模型供应商与额度：主链路 LLM 节点（P1/P2/P3/P5）需绑定可用模型 API Key；embedding 模型用于知识库索引。
3. 记录租户 ID、工作区地址、管理员账号，纳入 §7 交接清单。

### 1.2 应用导入（DSL）

1. 从设计基线导出 Dify DSL（应用配置描述文件，含工作流节点、变量、Prompt 引用），导入目标租户。
2. 导入后逐一核对节点与 D3 终稿节点一一对应：N0 消息接收 → N1 幂等去重 → **N2 版本变量校验（PR_VERSION / PT_VERSION 与 D4 §6.3 登记表比对，不一致阻断启动，D3 §9）** → N3/N4 意图识别（P1）→ N6 路由 → N7 知识检索 → N8 P2 知识问答 → N14 报价草稿 + 审批卡片 → N15/N15b 审批状态机与回调 → N16 发出报价单 → N22 发送答复 → N23 状态落库与埋点 → N24 跟单定时。
3. 检查 HTTP 节点指向：外部审批服务回调地址（N15b）、企微应用消息推送接口（N8/N14/N16/N22）、埋点写入接口（N23）。
4. **DSL 版本管理**：DSL 文件纳入版本控制，每次变更记录变更单；发布前必须按 D4 §6.4 先回归 D12 样本集且通过。

### 1.3 知识库上传

1. 使用 D5 §6 构建脚本 **build_kb.py**（位于 `D5_kb_builder/build_kb.py`，产出四个 jsonl）：kb_product / kb_pricing / kb_faq / kb_fx。
2. 在 Dify Knowledge 分别创建对应知识库，上传 jsonl 数据，选择**向量检索 + 关键词混合**模式，**Top-K = 4**（D3 §1 / D4 §8：检索为空直接走无答案路径，不扩大 K 重试）。
3. 核对密级元数据：kb_pricing 为 L3 机密（仅报价链路 N11 使用，检索层元数据过滤强制保证，不依赖模型自觉）；kb_fx 为 L2 受限；kb_product / kb_faq 为 L1 内部。**上传前确认 PII 已脱敏**（D5 §3.1）。
4. 上传后执行 D5 §6.3 自检：四库条数合计约 42 条（kb_pricing 每个 SKU 价格表必须为 1 个 chunk）、无完整手机号/邮箱、元数据含 doc_id / secret_level / version（正式版另须含 sku / category / effective_date）、无重复 content_hash、汇率 effective_date 在 7 天内。
5. 索引构建完成后抽查 3-5 条检索结果，确认命中片段与密级过滤符合预期。

### 1.4 变量配置

1. **版本变量**：`PR_VERSION`（报价规则版本，如 PR-0.9）与 `PT_VERSION`（Prompt 体系版本，如 PT-0.9）写入 Dify 工作流变量。**版本号三处必须一致**：知识库元数据 + Dify 工作流变量 + D4 §6.3 登记表（D4 §6.1）。
2. **置信度阈值**：P1 = 0.70 / P2 = 0.75 / P3 = 0.75，存储于工作流变量（D5 §5，非知识库）。**阈值必须留在工作流变量：误写入知识库将导致校验静默失效（代码节点读不到变量 → 阈值判定失效），上线前逐项确认变量面板可见。**
3. **报价阈值配置**（D5 §5，Phase 1 示例值）：单张报价单金额上限 > 20,000 USD、折扣率上限 > 15%、底价保护线（成交单价 < 底价 × 0.95）、汇率有效期 7 天。以上为示例值，**须在 Phase 1 与客户确认后发布为 PR-1.0**（D4 §6.3 待办）。
4. **运行成本变量**：单次对话输入 ≤ 4,000 token / 输出 ≤ 800 token；月成本上限示例 ≤ 200 元/月（D4 §8）。
5. 配置完成后导出变量清单快照，纳入备份范围（§6）。

### 1.5 IM 接入配置

1. 按 D6 配置企业微信自建应用：回调 URL（指向 Dify 应用入口）、Token、EncodingAESKey；钉钉备选形态下通道适配一致（D6 §5）。
2. 设置可见范围（业务员 / 主管 / 数字员工），群聊仅响应明确 @ 数字员工的消息，未 @ 不处理不计数（D6 §1/D3 N1）。
3. 联调 3 秒消息回执：N0 接收后回执正常返回；N21 静默归档仍正常回执（D3 §4.1）。
4. 审批卡片推送联调：N14 推送审批卡片，N15b 回调验签 + 幂等更新状态。
5. 跨境合规按 D6 §4 落地：仅传输脱敏后数据，传输链路启用加密，出境评估结论归档。

### 1.6 发布上线

1. 首次发布前完成 D12 样本集回归（D4 §6.2）：**样本集已落盘 50 条**（D12 终稿，覆盖直接可答 / 需人工确认 / 拒答三难度）；回归判据按 **D12 §6 A1–A7** 逐项验收：A1 意图识别准确率 ≥ 90%（内部验收阈值，对外仅宣称 CI 下界约 78%）、A2 报价输出格式 100% 合法、A3 报价金额正确率 ≥ 95%（±5% 容差内，分母仅实际发出单）、A4 金额/折扣超阈值 100% 转人工、A5 拒答类 100% 转人工不编造、A6 自动化率 ≥ 40% / 转接率 ≤ 60%（B1-b 口径，余量风险见下文）、A7 无关单静默归档（D3 §10）。
2. 灰度发布：先在样本集与测试群回归 → 通过后全量切换；旧版本保留可回滚（D4 §6.1）。
3. 上线检查清单：回调可达、回执 3 秒、**N2 版本变量校验（PR_VERSION / PT_VERSION 与 D4 §6.3 登记表比对，不一致阻断启动）**、知识库命中、审批卡片可达、埋点字段落库（N23）、监控告警接入（D9）。
4. **B1-b 余量风险检查（自动化率 ≥ 40% 为理想上界、余量 0pt）**：上线后须监控 auto 链路（P2 知识问答 / N14 报价草稿）实际命中率与成功率；实测成功率不足（如 s=0.90 → 36.7% 击穿目标）时触发 B1-a 后手（转接率 ≤ 60% 余量再分配 / 降低不必要 auto 占比），验收与看板须按 D3 §7.3 记录该监控项。

## 2. 私有化备选章节（Docker Compose）

### 2.1 定位与适用条件

私有化形态用于：无外网连接、数据必须本地留存、或客户指定私有化交付。与云端形态保持**同一 DSL 与同一知识库数据**，仅承载环境不同。迁移路径：云端导出的 DSL + D5 jsonl 可直接导入私有化实例，降低双轨差异。

### 2.2 最低配置建议

| 资源 | 建议值 | 说明 |
|------|--------|------|
| CPU | 4 核（8 核推荐） | 低于 4 核时建议走 §4 低配降级 |
| 内存 | 16 GB（32 GB 推荐） | 承载 db / redis / vector / api / worker / web |
| 磁盘 | 200 GB SSD | 知识库索引 + 业务数据 + 备份副本 |
| 网络 | 出网带宽 10 Mbps（若调用云端模型 API） | 完全离线则无需 |

> 以上为示例建议值，**正式规格以 Phase 1 搭建实测为准（需核实）**。

### 2.3 服务清单（Docker Compose）

| 服务 | 职责 | 备注 |
|------|------|------|
| api | 应用编排 API / 工作流引擎入口 | Dify 核心 |
| worker | 异步任务（知识库索引、工作流执行） | 低配时限制并发数 |
| web | 前端控制台 | 管理端 |
| db | PostgreSQL，元数据与业务数据 | 数据卷挂载，纳入备份 |
| redis | 缓存与队列 | 数据卷挂载（纯缓存，**不纳入备份/恢复**，见 §6.2） |
| vector | 向量数据库（知识库索引） | 数据卷挂载，故障见 §5 |
| sandbox | 代码节点执行环境 | 承载 D3 路由/阈值 Code 节点（L5 阈值校验等） |
| approve-svc | 外部轻量审批服务（草稿存储 + 状态机 + 签名回调 + 4h 超时扫描） | 自研组件，D3 §4.2 |

部署要点：

1. **镜像版本化**：所有服务镜像固定 tag（不使用 latest），版本登记表记录镜像 digest，回滚时切换上一版本镜像（D3 §4.2 回滚口径）。
2. **数据卷挂载**：db / redis / vector 数据卷与容器解耦，容器重建不丢数据。
3. **环境变量**：.env 集中管理（模型 API Key、回调密钥、PR_VERSION / PT_VERSION、阈值配置），.env 纳入备份但**禁止提交到代码库**。
4. **健康检查**：每个服务配置 healthcheck；一键脚本以「api + worker + vector + approve-svc 健康」作为启动成功判据。
5. **外部依赖**：Dify 工作流所需的 LLM 模型 API 在私有化形态下仍走云端 API（有网场景）或切换本地模型（无网场景走 §2.6 或 §4 降级）。

### 2.4 与云端形态的差异与回归要求

1. 私有化实例上线前同样须执行 D12 回归（D4 §6.4 唯一口径：任何变更先回归且通过）。
2. 双轨共用同一份 DSL 基线；私有化形态若改动节点（如审批服务连接方式），须记录变更单并同步更新版本登记。
3. 冒烟验收口径：一键脚本启动 → 冒烟测试 ≤ 30 分钟（Phase 3 双轨验收，见 §0）。

### 2.5 enterprise-agent 备选章节

1. **定位**：自研离线改造版（基于开源框架二次开发），**仅用于无网/低配环境演示，Phase 3 备选**（D3 §1）。不作为生产主推形态。
2. **上游锁定**：上游项目名与版本须锁定并登记，统一记录于 **§8 待办第 2 条**（不在本节重复自指）；当前为初稿，具体上游项目与版本待 Phase 1 搭建时确定并回填本文档（需核实）；锁定后任何上游升级须记录变更单并回归 D12。
3. **语义等价要求**：若启用，须实现与 Dify 工作流**同等节点语义**（同一套路由 / 阈值 / 校验，含金额阈值、置信度阈值、4h 超时 escalate），并通过同一份 D12 样本集回归，否则不得作为演示形态（D3 §8）。
4. **部署形态**：离线单机部署，模型使用本地模型（无外网依赖）；回调、审批卡片、埋点接口按 D6/D9 对齐。

## 3. 一键部署脚本说明

> 本节说明脚本**结构描述与使用步骤**；可运行完整脚本由 Phase 1 搭建时产出并回填（需核实）。初稿阶段以结构规范为准。

### 3.1 脚本结构

```
deploy/
├── deploy.sh / deploy.ps1        # 一键部署入口（云端：开通检查+配置；私有化：启动编排）
├── rollback.sh / rollback.ps1    # 一键回滚到上一版本（镜像 tag + 数据卷不动）
├── docker-compose.yml            # 私有化服务编排（§2.3 服务清单）
├── .env.example                  # 环境变量模板（模型 Key / 密钥 / 版本变量 / 阈值）
├── healthcheck.sh                # 健康检查（api / worker / vector / approve-svc）
├── backup.sh                     # 备份脚本（§6 频率与范围）
├── restore.sh                    # 恢复脚本（§6 恢复步骤）
├── smoke_test.sh                 # 冒烟测试（N0 回执 / P1 意图 / 检索命中 / 草稿生成）
└── config/
    ├── dsl/                      # 云端导出的 Dify DSL 文件（版本化）
    └── kb/                       # D5 构建脚本产物 jsonl（版本化）
```

### 3.2 使用步骤

> 声明（审计#14 修订）：本节一键部署/回滚脚本为**结构规范**，脚本文件尚未落盘；Phase 1 搭建时按本节结构回填 deploy/ 目录并实测后，方可宣称一键部署可用。

1. **云端主推**：运行入口脚本的「云端模式」：检查租户可达性 → 导入 DSL → 上传知识库（或校验已存在）→ 写入变量（PR_VERSION / PT_VERSION / 阈值）→ 执行 smoke_test.sh → 输出验收结论。
2. **私有化备选**：先准备服务器（§2.2 配置）→ 编辑 .env（密钥与变量）→ 执行入口脚本启动 compose → 等待 healthcheck 全绿 → 执行 smoke_test.sh → 输出验收结论。
3. **回滚**：任一验收不通过，运行 rollback 脚本切换上一镜像版本；数据卷不参与回滚，避免丢数据。
4. **幂等性**：脚本重复执行不得产生重复导入（按 DSL 版本号与知识库哈希判重）。

### 3.3 安全与校验要求

1. 脚本不得硬编码任何密钥；密钥仅从 .env / 环境变量读取。
2. 执行前打印将要影响的资源清单（镜像、数据卷、端口），高影响操作须人工确认后再继续。
3. 脚本输出包含成功/失败 JSON 摘要（节点数、知识库条数、冒烟项结果），供验收留档。

## 4. 低配环境运行建议

### 4.1 资源下限与判断

| 资源 | 下限 | 低于下限的处理 |
|------|------|----------------|
| CPU | 2 核 | 仅能承载演示型负载；开启 §4.2 全部降级 |
| 内存 | 8 GB | 关闭 worker 多并发，限制为 1；vector 与 db 同机共存 |
| 磁盘 | 100 GB | 缩减历史备份保留份数 |

> 下限值供初稿参考，**以 Phase 1 实测为准（需核实）**。

### 4.2 降级措施

1. **并发降级**：worker 并发数降至 1，工作流串行执行；关闭非必需定时任务（N24 跟单定时可延后执行）。
2. **检索降级**：维持 Top-K = 4 不扩大；检索为空直接走无答案路径并转人工（D4 §8），避免检索放大算力。
3. **上下文限制**：单次对话输入 ≤ 4,000 / 输出 ≤ 800 token，超限截断 context 并转人工（D4 §8）。
4. **模型降级**：有网场景使用低参数云端模型 API；无网场景切换本地模型或启用 enterprise-agent 备选形态（§2.5），但须保证同等节点语义与 D12 回归（D3 §8）。
5. **成本控制**：月成本上限示例 ≤ 200 元/月；达到 80% 告警，达到 100% 降级为「仅高价值意图走 LLM」（D4 §8）。

## 5. 故障排查表

| # | 现象 | 可能原因 | 处置 |
|---|------|----------|------|
| 1 | 回调验签失败（N0/N15b 报签名错误） | EncodingAESKey / Token 不一致；回调 URL 配置错误；消息时间戳偏移 | 核对 D6 配置三要素（URL/Token/EncodingAESKey）；检查回调服务时间同步（NTP）；查看验签日志定位失败节点；密钥轮换按 D6 §6 变更管理执行 |
| 2 | 消息未在 3 秒内回执 | 回调链路超时；回调地址不可达；网络抖动 | 检查回调 URL 可达性与超时设置；重试 1 次；仍失败按 D3 N0 失败策略处理并告警；排查幂等去重是否误判（D3 N1） |
| 3 | 知识库未命中 / 检索为空 | 知识库未上传或索引未构建；切分异常（价格表被切开）；Top-K 检索无结果 | 执行 D5 §6.3 自检核对条数与 chunk 完整性；重建索引；**不扩大 K 重试**，走 P2 无答案路径转人工（D4 §8）；确认 kb_pricing 整块不切分 |
| 4 | 报价流程超时转人工 | N15 确认队列超 4h；审批服务 4h 超时 escalate（终态，绝不自动发出报价） | 确认超时为预期终态：escalate 并同时 W2 通知主管接单（D3 §4.3 双口径）；检查审批服务 4h 扫描任务是否运行；人工接单处理 |
| 5 | 模型限流 / LLM 节点连续失败 | 模型 API 限流、额度耗尽、网络故障 | 每个 LLM 节点最多重试 1 次；**同一节点连续失败 ≥ 5 次 → 熔断该链路，全量转人工并告警**（D3 §5）；检查月成本告警（80%）与降级阈值（100%）（D4 §8） |
| 6 | 变量缺失 / 版本不一致 | PR_VERSION / PT_VERSION 三处（知识库元数据、Dify 变量、D4 §6.3 登记表）不同步 | 核对三处版本号并统一；按 D4 §6.2 变更流程重新发布；不得在版本不一致状态下报价 |
| 7 | 企微回调加解密失败 | EncodingAESKey 错误、密文被截断、随机串异常 | 校验密钥与 D6 配置一致；查看回调原始报文与加解密日志；联系企微后台核对应用 Secret；密钥轮换走 D6 §6 |
| 8 | 向量库异常（检索报错/索引损坏） | vector 服务未启动、数据卷损坏、索引版本不兼容 | 检查容器健康状态；重启 vector 服务；损坏时重建索引（从 D5 jsonl 重灌）；验证恢复后 Top-K=4 检索命中 |
| 9 | 审批卡片未推送 / 回调未到达 | 审批服务离线；审批服务回调地址配置错误；卡片推送被企微拦截 | 检查 approve-svc 健康状态与日志；核对 N14 推送目标与 N15b 回调地址；推送失败重试 1 次 → N20 转人工（D3 §4.1） |
| 10 | 报价被阈值拦截但金额看似正常 | 阈值边界口径已统一（D5 §5 与 D4 §4.1/§4.2/V5 均为「> 20,000 触发拦截、= 20,000 放行」）；汇率过期 | 核对 D5 §5 阈值配置与工作流变量；检查 fx 有效期（超 7 天标 expired 不得报价）；拦截属安全侧预期行为，异常拦截查阈值配置与汇率更新任务 |
| 11 | 埋点数据缺失（D9 看板） | N23 写失败；埋点字段不齐 | N23 写失败走本地队列重试，不阻断答复（D3 §4.1）；核对 D9 §4 埋点字段（时间戳字段）与 N23 落库表；队列积压告警 |
| 12 | 汇率未更新 / 报价使用旧汇率 | 汇率抓取任务失败；validity_days=7 过期未标 | 检查每工作日更新任务（周末/节假日不更新）；超 7 天无更新标记 expired，P3 走「无价格资料」路径，不得用旧汇率报价（D5 §4.1）；修复后重灌 kb_fx |

> 处置原则（D3 §5 / D4 §7）：任何失败节点按「重试 1 次 → 仍失败转人工」兜底；熔断条件独立触发；所有故障处置记录留痕，作为 D9 埋点与 §7 SLA 统计依据。

## 6. 备份与恢复演练

### 6.1 备份范围与频率

| 对象 | 内容 | 频率 | 保留 |
|------|------|------|------|
| 知识库 | 原文（D5 raw/clean）+ 向量索引 + jsonl 产物 | 每日增量 + 每周全量 | 默认保留 30 天（可配置）；L3 价格数据最短保留 + 到期即删 |
| 业务数据 | 询盘记录（msg_id/content/sender_id/chat_id/ts）、审批草稿与状态、N23 埋点数据 | 每日增量 + 每周全量 | 默认保留 30 天（可配置） |
| 配置与版本 | Dify DSL、.env（密钥除外加密存放）、PR_VERSION / PT_VERSION、阈值配置、镜像版本登记 | 每次变更即备份 | 随版本归档，保留可回滚点 |

**删除机制（D5 §8 / D6 §4）**：知识库删除须同时清除向量、原文、备份副本，并出具删除凭证留档备查；默认保留期 30 天为基线，可配置。

### 6.2 恢复演练

1. **演练频次**：上线前至少 1 次完整恢复演练；运行期每季度 1 次（建议值，需核实）。
2. **恢复步骤**：
   1. 从每周全量 + 每日增量恢复 db / vector 数据卷（**redis 为纯缓存卷，不纳入备份与恢复**——容器重建或重启后由应用自动重建缓存，避免恢复脏缓存覆盖在线状态）；
   2. 恢复 .env 与 DSL（校验 PR_VERSION / PT_VERSION 三处一致）；
   3. 启动服务，等待 healthcheck 全绿；
   4. 执行 smoke_test.sh 验证 N0 回执、知识库命中、草稿生成；
   5. 抽验最近一笔已完成询盘记录与审批状态可回溯；
   6. 记录恢复时长与结论，纳入 §7 SLA（RTO/RPO）统计。
3. **回滚点**：每次变更前导出版本快照（镜像 tag + 数据 + DSL），失败时一键回滚上一版本（§3.2）。
